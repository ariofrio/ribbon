# Ribbon on bb 0.46

Implementation: [PR #198](https://github.com/ariofrio/ribbon/pull/198). Migration target: [upstream bb 0.46.0](https://github.com/get-bb/bb/releases/tag/desktop-v0.46.0), with its bundled [Plugin SDK 0.6.37](https://github.com/get-bb/bb/blob/desktop-v0.46.0/packages/plugin-sdk/package.json). The running server reports `0.46.1-ariofrio.7`. The fork's [version preparation script](https://github.com/ariofrio/bb/blob/desktop-v0.46.1-ariofrio.7/scripts/prepare-fork-version.mjs) increments the upstream patch before adding its suffix, so this runtime corresponds to upstream 0.46.0. Fork build numbers do not advance Ribbon's migration target.

Baseline: [Ribbon's bb 0.45 migration](https://github.com/ariofrio/ribbon/pull/169), including its subsequent title-policy correction and [coverage report](bb-0.45.md). The repository now has five plugins; Model mentions was added after that upgrade. Manifests, standalone lockfiles, the workspace lockfile, marketplace and project plugin inventory, harness dependencies, registry pin and fork lock were reconciled. The sole declared fork remains Thread stages, derived from bb's Thread list.

## Remaining public API limits

The [public navigator](https://github.com/get-bb/bb/blob/desktop-v0.46.0/packages/plugin-sdk/src/app-contract.ts#L3476) can add, select and reveal a terminal tab. It does not expose terminal focus or hiding, nor select/close arbitrary existing Side chat tabs. Missing keyboard shortcuts therefore retains the narrowly scoped panel visibility/storage and DOM focus bridge. Its own panel opener cannot control another plugin's already-open tab. This is narrower than the gap recorded in the [0.45 audit](bb-0.45.md).

[Public PR metadata](https://github.com/get-bb/bb/blob/desktop-v0.46.0/packages/plugin-sdk/src/app-contract.ts) still omits check counts and requested reviewer names. Thread stages retains its richer GitHub RPC lookup and public status fallback to preserve tooltip detail.

## Separate proposals

Register stage changes as global thread actions so the native header and other plugins can offer Ribbon stages, using the [action registration API](https://github.com/get-bb/bb/blob/desktop-v0.46.0/packages/plugin-sdk/src/app-contract.ts). This needs a policy decision about target eligibility and ordering; the compatibility migration retains the sidebar stage workflow.

Offer voice input for saved prompts through the [public voice textarea contract](https://github.com/get-bb/bb/blob/desktop-v0.46.0/packages/plugin-sdk/src/app-contract.ts). Draft insertion, scheduling and optional title-service selection from the [previous report](bb-0.45.md) remain separate product work.
